# iOSショートカット構築ガイド

iPhone / iPadのApple純正「ショートカット」アプリから習慣を記録し、Xの投稿画面を開きます。記録はAPIへの保存時点で完了し、Xへの投稿確定は手動です。設定の基準は[Habit README](README.md)と[API実装](../../src/workers/habit.ts)です。

## 前提準備

1. [セットアップとデプロイ](README.md#セットアップとデプロイ)に従い、Habit用D1、マイグレーション、WorkerとPagesの配信を済ませます。サーバー管理者が`HABIT_TOKEN`に推測困難なランダム値を設定します。
2. iPhone / iPadに「ショートカット」アプリを用意し、ネット接続を確認します。オフライン保存は未実装です。
3. ショートカットに`HABIT_TOKEN`を設定します。`https://haroin57.com/habit`は公開ログの閲覧専用です。

ショートカット内のトークンは平文で参照できます。トークン入りのショートカットを共有しないでください。共有用にはトークンを削除した複製を使用します。

本ガイドでは`Authorization: Bearer <HABIT_TOKEN>`を使います。実装は`X-Admin-Secret: <ADMIN_SECRET>`にも対応しますが、`HABIT_TOKEN`が未設定の場合、管理者認証でも書き込みは503になります。

## クイック記録ショートカット

「ショートカット」で新規作成し、次の順にアクションを追加します。アクション名や設定の表示はOSのバージョンによって異なります。

| 手順 | アクション | 設定・処理 |
| --- | --- | --- |
| 1 | テキスト → 変数を設定 | `HABIT_TOKEN`の値を入力し、変数`Token`に設定します。 |
| 2 | URL | `https://haroin57.com/api/habit/quick`を設定します。 |
| 3 | URLの内容を取得 | 手順2のURLを使用し、方法を`POST`にします。ヘッダーに`Authorization` = `Bearer `＋変数`Token`（半角スペースを1個挿入）、`Content-Type` = `application/json`を設定します。リクエスト本文を`JSON`にし、テキスト項目`action_type` = `toilet_sq_en`、数値項目`value` = `1`を追加します。 |
| 4 | 入力から辞書を取得 → 変数を設定 | 手順3の応答を辞書として取得し、変数`Response`に設定します。 |
| 5 | 辞書の値を取得 → If | `Response`の`error`に値があれば、その値を「アラートを表示」で表示し、「このショートカットを停止」で終了します。 |
| 6 | 辞書の値を取得 → If | `Response`の`status`が`ok`以外なら、応答を表示して終了します。 |
| 7 | 辞書の値を取得 → If | `Response`の`tweet_text`を取得します。空なら「投稿文を取得できません。保存状況を確認してください。」と表示して終了します。 |
| 8 | URLエンコード | 手順7の`tweet_text`だけをエンコードします。URL全体はエンコードしません。 |
| 9 | URL → URLを開く | `https://twitter.com/intent/tweet?text=`の末尾に手順8の結果を変数として挿入し、開きます。 |

本文の例は次のとおりです。`value`は省略可能で、指定する場合は数値の`1`だけを受け付けます。`30`などを指定して回数を変更することはできません。

```json
{
  "action_type": "toilet_sq_en",
  "value": 1
}
```

HTTPエラーがJSONとして返った場合は手順5で終了します。通信やHTTPエラーによって「URLの内容を取得」自体が停止した場合も、投稿画面を開かず、後述の手順で保存状況を確認します。

Xアプリを直接開く場合は、手順9を`x://post?message=`＋手順8の結果に変更します。アプリが利用できない場合はWeb Intentを使用します。代替の投稿画面を開く際に記録用POSTを再実行すると重複加算するため、取得済みの投稿文を使用します。X側で文面を確認し、投稿ボタンを押します。

初回実行は実際の記録になります。通信やURLを開く権限を求められた場合は内容を確認して許可します。動作確認後、ショートカットを複製し、名前と`action_type`だけを変更します。

### action_type一覧

| ショートカット名 | action_type | 記録内容 |
| --- | --- | --- |
| トイレSQ30＋英語 | `toilet_sq_en` | スクワットを30回、英語を1レッスン加算します。 |
| ジャンプSQ20 | `jump_sq` | スクワットを20回加算します。 |
| スクワット30 | `squat30` | スクワットを30回加算します。 |
| 腕立て1セット | `pushup_set` | 腕立てを1セット加算します。 |
| 腹筋ローラー1セット | `abs_set` | 腹筋を1セット加算します。 |
| プランク90秒 | `plank` | 腹筋を1セット加算します。秒数の保存は行いません。 |
| 英語1レッスン | `english` | 英語を1レッスン加算します。 |
| スクショ資料保存 | `screenshot` | 資料スクショを1枚加算します。画像の保存・アップロードは行いません。 |
| 仕事25分初動 | `work_focus` | 仕事初動を完了に設定します。再実行しても完了のままです。 |

`work_focus`以外は実行のたびに加算します。ショートカットは運動の実施、英語学習、タイマー計測などを代行しません。

## 夜の総括ショートカット

Webサイトの記録画面は撤去しました。夜の総括はショートカットから`POST https://haroin57.com/api/habit/daily-close`へ送信します。クイック記録と同じBearer認証とJSON形式を使います。

完了フラグ、バイク分数、公開メモ、翌日To-Doの入力仕様は[API一覧](README.md#api)で確認できます。総括は完了フラグとバイク分数を当日の値に置き換え、クイック記録の加算値を維持します。実績とメモは`/habit`に公開され、To-Doは非公開です。レスポンスの`tweet_text`はクイック記録と同様にXの投稿画面へ渡せます。

## ホーム画面・ロック画面・背面タップへの配置

### ホーム画面

ショートカットの編集画面上部のメニューから「ホーム画面に追加」を選択し、名前とアイコンを設定して追加します。クイック記録と夜の総括をそれぞれ配置します。ウィジェットを使う場合はホーム画面の編集から「ショートカット」を追加し、編集メニューで対象のショートカットまたは専用フォルダを指定します。[Appleのショートカット更新案内](https://support.apple.com/ja-jp/101583)でもホーム画面への追加メニューを確認できます。

### ロック画面とコントロールセンター

iOS 18以降では、ロック画面下部のコントロールにショートカットを配置できます。ロック画面を長押しし、「カスタマイズ」→「ロック画面」から下部の既存コントロールを外して「コントロールを追加」を選びます。「ショートカット」の実行用コントロールを追加し、対象に「トイレSQ30＋英語」などを指定します。時計下のウィジェット欄とは別の設定です。[AppleのiOS 18ショートカット更新案内](https://support.apple.com/ja-jp/121131)に対応機能が記載されています。

コントロールセンターも編集画面の「コントロールを追加」からショートカットの実行用コントロールを選び、対象を指定します。実行時にロック解除が求められる場合は解除します。

### 背面タップ

対応するiPhoneで「設定」→「アクセシビリティ」→「タッチ」→「背面タップ」を開き、「ダブルタップ」または「トリプルタップ」に対象のショートカットを割り当てます。背面タップはiOS 14以降のiPhone 8以降が対象です。誤操作も実際の加算になるため、配置後に動作を確認します。[Appleの背面タップ設定手順](https://support.apple.com/ja-jp/111772)を参照できます。

iPadでもショートカットを利用できます。iCloudのショートカット同期を有効にした端末間では同期されますが、背面タップはiPhone向けの機能です。

## トラブル時

| 症状・応答 | 確認と対処 |
| --- | --- |
| `401 Unauthorized` | `Authorization`の値を`Bearer `＋正しいトークンにします。余分な改行・空白を除去し、サーバーと同じ値か確認します。 |
| `503` | `error`が`HABIT_TOKEN is not configured`なら管理者がトークンを設定してWorkerを再デプロイします。`Habit database is not configured`なら`HABIT_DB`の接続設定を確認します。 |
| `400` | `action_type`の綴りと`value`が数値の`1`か確認します。本文はJSONオブジェクトにします。総括ではフラグ、分数、文字数制限も確認します。 |
| `404` / `405` | クイック記録は`POST /api/habit/quick`です。URLの綴りとHTTPメソッドを確認します。 |
| `415` | 本文形式をJSONにし、`Content-Type: application/json`を設定します。 |
| `413` | 本文が16 KiBを超えています。必要な項目だけを送信します。 |
| `500` | サーバー管理者がD1のマイグレーション、接続、Workerログを確認します。保存状況を確認してから再実行します。 |
| 通信失敗・反応がない | まずサイトが開くか確認します。応答が届かなくても保存済みの場合があるため、再実行前に認証付き`GET /api/habit/today`の当日合計を確認します。自動再試行や連打は避けます。 |
| 保存されたがXが開かない | `tweet_text`の有無と一度だけURLエンコードしたかを確認します。Xアプリ用URLが使えない場合は、取得済みの投稿文でWeb Intentを開きます。記録用POSTは再実行しません。 |
| 日付が前日になる | 対象日はJST午前4時に切り替わります。0:00〜3:59の記録は前日分です。応答の`target_date`を確認します。 |

疎通確認には`GET https://haroin57.com/api/habit/today`も使えます。同じBearerヘッダーが必要で、Safariのアドレス欄から開くだけでは認証できません。未記録日の`log: null`は正常です。`/today`は閲覧用で、記録用POSTの代わりにはなりません。

APIはクイック記録だけではありません。総括は`POST /api/habit/daily-close`、今日の閲覧は`GET /api/habit/today`、公開ログ取得は認証不要の`GET /api/habit/stats`、今日のTo-Do完了は`POST /api/habit/todo/complete`です。入力仕様は[API一覧](README.md#api)で確認できます。
