# ADR-001: NFC縦断スライスを既存スタックへ追加する

状態: このリポジトリ向けの実装判断です。要件v2.1との相違を明示します。

## 判断

既存のReact/Vite、React Router、Cloudflare Worker、Habit D1を維持します。Next.js/PostgreSQLへサイト全体を移行しません。新しいnpm依存は追加しません。公開`/habit`は閲覧専用を維持し、新しい本人専用操作を`/control`へ隔離します。これは新しい要件による操作UIで、撤去済みの旧Habit入力画面の復元ではありません。

理由は、既存のMarkdown生成・SSR・Pages Git連携を保ち、NFC契約と状態管理の最小縦断スライスを独立して確認するためです。Next.js/PostgreSQLを採用する要件は未対応であり、この判断を同等実装と偽りません。将来、APIのドメイン層を移植できます。

## 整合性と保存

- 状態と台帳の権威は`becs_snapshots.document_json`です。生活状態revisionとは別の単調増加sequenceを競合制御に用います。拒否・タグ編集でも保存sequenceは増えますが、生活状態revisionは変わりません。
- 先頭primaryでロードし、次のsequenceの一意INSERT、スキャン応答、監査、変更された投影を同一D1バッチで確定します。連番を検証するDBトリガーにより、圧縮済みの旧sequenceへの書き込みも拒否します。競合時はバッチ全体をロールバックし、元のIDを保持して再評価します。競合上限時は503で未確認として扱います。
- nfc_tags、nfc_bindings、device_nodes、routine_sessions、daily_plans、device_commands、override_sessionsは同一バッチの検索用投影です。PostgreSQLの全正規化テーブル一覧とは一致しません。日次タスクとポリシーは文書内で保持します。
- コマンドは永続的なpull型outboxです。別のoutbox_messagesテーブルやキューブローカーを追加せず、端末は自分宛の最新revisionを取得してACKします。cronで有効期限を更新し、失効した要求は端末が破棄します。
- スキャン結果は90日保持します。スナップショットは日次の最終版と最新版に圧縮し、制御文書内の終了済みセッションは直近200件に限定します。検索用セッション履歴は90日保持します。保持期限後も古いタッチは時刻検証で拒否します。監査、旧スナップショット、終了済み投影は90日で削除し、最新状態は保持します。日次集計は最大366件です。
- 端末トークンの原文は発行応答だけに含め、スナップショット・監査・投影・再送応答には記録しません。本人のレビューとTo-Doは認証APIに限ります。

## 制御の段階導入

初期はOBSERVEだけを発行します。禁止アプリ終了、DNS遮断、MDM、照明・空調の起動は有効化しません。実機の必須通信と解除経路の検証なしにRESTRICTへ進めません。PCのローカル解除は実装済みですが、macOSの実配備試験は残っています。ESP32はローカル判定の参照実装とホストC++試験までです。

## 残る実装・配備

- PostgreSQL/Next.jsへの移行を採用する場合の独立計画。
- 自己申告ではないPC Agentの集中計測方式の実機比較、DNS専用プロファイルの連携、照明・対応空調のメーカーAPI。
- ESP32の配線/コンパイル/配備、認証済みシリアルBridgeと選択した動画プレイヤーの統合。
- iOS 100回試験、NFRのp95、DNSの伝播、OS復帰/ロック状態の実測。
- 任意MDM PoCと週次運用評価。

実機未確認の機能を適用済みとは表示しません。全ロードマップ完了ではなく、ソフトウェアのNFC縦断スライスと後続フェーズ向けの基盤です。
