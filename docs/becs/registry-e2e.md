# タグ有効化とShortcuts紐付けのブラウザ検証

## 再現した不具合

Cookieで認証済みのブラウザから新しいタブを開くと、タブ固有の`becs_csrf`がない状態でも`GET /state`は成功します。旧画面は管理用ボタンを表示しましたが、有効化のPATCHは401になり、タグはDRAFT、紐付けは未作成のままでした。Chrome上の実画面と実Workerハンドラーで再現しました。本番で報告された失敗がこの条件だったかは、本人の操作ログなしでは確定していません。

## 修正

- 操作認証がこのタブにない場合は、管理ボタンを表示せず本人認証へ進みます。クライアントも未認証の更新送信を防止します。
- 操作時に401を受けた場合は古い認証状態を破棄し、本人認証へ戻します。APIの認証・CSRF検査は維持します。
- 端末一覧に端末IDを表示します。有効なiPhoneが1台なら紐付け先へ選択します。複数台の場合は明示的に選択します。
- タグの下書き・有効状態と次の操作を表示し、選択した端末への紐付け済みボタンを無効化します。有効化はタグ編集欄やiPhoneの入力に依存しません。

## 検証結果

Chrome・ローカルの実フロントエンド・実Workerハンドラー・分離SQLiteを使用し、次を確認しました。APIリクエストは検証用ハンドラーへ転送し、本番へ送信していません。

- Cookieだけがある新しいタブでは本人認証を表示し、有効化ボタンは表示しません。
- 本人認証後に端末IDを確認でき、1台の検証用iPhoneが選択されます。
- ラベル・設置場所の編集欄が空のまま、起床・外出の両タグを有効化できます。
- それぞれにIOS_SHORTCUTSの有効な紐付けを作成でき、APIでACTIVEのタグ2件・有効な紐付け2件を確認しました。
- 操作認証が失効した場合は本人認証へ戻り、拒否された無効化でタグ状態が変更されないことを確認しました。

本番の既存タグ・端末・資格情報はこの検証では変更していません。本番反映後は`/control/tags`で本人認証し、起床・外出それぞれの「有効化」→「Shortcutsへ紐付け」を実行します。複数のiPhoneがある場合は、ショートカットに設定した端末IDと同じ端末を選択します。
